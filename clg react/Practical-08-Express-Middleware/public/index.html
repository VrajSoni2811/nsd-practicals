Practical 08: Viva Voce & Middleware Mechanics

Comprehensive questions on Express middleware types, lifecycle, next() semantics, and error handling.

Q1: What is Middleware in Express.js and what can it perform?

Middleware functions are functions that have access to the request object (req), response object (res), and the next middleware function in the application’s request-response cycle. They can:

  1. Execute any code (logging, metrics, authentication).
  2. Make changes to the request and response objects (e.g. parsing JSON, attaching req.user).
  3. End the request-response cycle (e.g. sending HTTP 401 or 400).
  4. Call the next() middleware in the stack.

Q2: What is the significance of the next() function?

If the current middleware does not end the request-response cycle, it must invoke next() to pass control to the subsequent middleware function in the stack. Failing to invoke next() or send a response leaves the HTTP client hanging indefinitely until a network timeout occurs.

Q3: Name the 5 fundamental types of middleware in Express.js.

1. Application-level middleware: Bound to app.use() or app.METHOD().
2. Router-level middleware: Bound to an instance of express.Router().
3. Built-in middleware: Bundled in Express, such as express.json() and express.static().
4. Third-party middleware: Installed via npm, such as cors, morgan, or helmet.
5. Error-handling middleware: Defined strictly with four parameters: (err, req, res, next).

Q4: How does Express identify an Error-Handling Middleware?

Express checks function arity (the number of declared parameters via fn.length). Standard middleware functions take 2 or 3 arguments: (req, res, next). Error-handling middleware must explicitly declare exactly four arguments: (err, req, res, next). If you omit next, Express treats it as standard middleware and will not route errors to it.

Q5: What happens when you pass an argument to next(error)?

When any value (except the string 'route') is passed to next(), Express skips all remaining standard middleware and router handlers and routes directly to the next registered Error-handling middleware.

Q6: Why is middleware order critical in Express?

Middleware executes strictly in the sequence it is registered with app.use(). For instance, body parsing middleware (express.json()) must be placed before any route handlers that read req.body, and error-handling middleware must be registered after all routes so it can catch propagated errors.

Q7: How does Rate Limiting protect web servers?

Rate limiting restricts the number of requests a given client or IP address can make within a specified timeframe. It prevents denial-of-service (DoS) attacks, brute-force password guessing, and API scraping by responding with HTTP 429 Too Many Requests once the limit is breached.

Q8: How can custom middleware attach data to the Request object?

Since the req object is a mutable JavaScript reference passed through all middleware functions in a single lifecycle, middleware can attach custom properties such as req.user = decodedToken, req.startTime = Date.now(), or req.trace = [] for subsequent handlers to inspect.
