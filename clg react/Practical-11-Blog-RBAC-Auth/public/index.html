Practical 11: Viva Voce & Security Architecture

Comprehensive questions on JWT structure, RBAC, password security, and stateless sessions.

Q1: What is JWT (JSON Web Token) and what are its three components?

A JSON Web Token (JWT) is a compact, URL-safe means of representing claims to be transferred between two parties. It consists of three parts separated by dots (.):

  1. Header: Specifies the token type (JWT) and cryptographic hashing algorithm (e.g. HS256).
  2. Payload: Contains claims (user ID, username, role, expiration timestamp exp).
  3. Signature: Generated by signing the encoded header and payload with a server secret key to verify data integrity.

Q2: What is Role-Based Access Control (RBAC) and how was it implemented here?

RBAC is a security paradigm that restricts system access based on assigned user roles. We implemented a higher-order middleware authorizeRoles('Admin', 'Author'). It inspects the claims decoded from the JWT; if the role is authorized, control proceeds to the controller. Additionally, fine-grained object ownership was implemented so Authors can only edit/delete their own articles, while Admins enjoy global override privileges.

Q3: Why are JWTs called 'Stateless' and what advantage does that offer?

Unlike traditional session-cookie architectures where the server stores session IDs in RAM or Redis, a JWT contains all user identity and permission claims directly inside the signed payload. The server does not need to perform a database query on every request; it simply validates the cryptographic signature locally, enabling effortless horizontal scaling across multiple servers.

Q4: How should JWTs be transmitted in HTTP requests?

The standard protocol is to send the token in the Authorization request header prefixed by Bearer :
Authorization: Bearer <jwt_token_string>. The server splits the header by space and extracts the token at index 1.

Q5: What happens when a JWT expires?

When the current epoch time exceeds the token's exp timestamp, the jwt.verify() library throws a TokenExpiredError. The server responds with HTTP 401 Unauthorized, prompting the client to refresh the token using a refresh token or log in again.

Q6: What is the difference between Authentication and Authorization?

- Authentication (AuthN): Verifying who the user is (e.g. validating email and password credentials). Returns HTTP 401 Unauthorized if unauthenticated.
- Authorization (AuthZ): Verifying what permissions an authenticated user has (e.g. determining if a Reader has permission to delete an article). Returns HTTP 403 Forbidden if permission is denied.

Q7: How are password hashes secured in production applications?

Passwords must never be stored in plaintext. They are salted (appending random cryptographic strings) and hashed using adaptive, compute-intensive algorithms like bcrypt or argon2. The work factor (cost salt rounds) ensures brute-force and rainbow-table attacks are computationally infeasible.

Q8: How can a compromised JWT be revoked before its expiration?

Because JWTs are stateless, they remain valid until expiration. To revoke a token immediately:

  1. Maintain a fast in-memory token blacklist (e.g. in Redis) checked on each request.
  2. Implement short-lived access tokens (e.g. 15 minutes) paired with revocable refresh tokens stored in the database.
  3. Increment a tokenVersion counter on the user document and embed it in the token payload.
