Practical 07: Viva Voce & Conceptual Architecture

Comprehensive Q&A covering MongoDB Atlas, Mongoose ODM, NoSQL vs SQL, and Aggregation Pipelines.

Q1: What is MongoDB Atlas and how does it differ from a local MongoDB instance?

MongoDB Atlas is a fully managed cloud database service hosted across AWS, Google Cloud, or Azure. It eliminates the operational overhead of database configuration, automated patching, hardware provisioning, and automated horizontal scaling. In contrast, a local MongoDB instance runs as a standalone daemon (mongod) on your local operating system, requiring manual backups, replication management, and local resource allocation.

Q2: What is Mongoose and why is it used with Express.js?

Mongoose is an Object Data Modeling (ODM) library for MongoDB and Node.js. Although MongoDB is schema-less by nature, enterprise web applications require structured data integrity. Mongoose enforces strict schema definitions, data type validation, pre/post middleware hooks, virtual computed properties, and relationship population, making database operations predictable and robust.

Q3: Explain the structure and purpose of a MongoDB Connection String URI.

A standard Atlas SRV URI follows this format: mongodb+srv://<username>:<password>@cluster0.abcde.mongodb.net/<dbname>?retryWrites=true&w=majority. The mongodb+srv prefix indicates DNS Seedlist Connection which dynamically resolves replica set members. The query parameter retryWrites=true ensures transient network failures retry writes automatically, and w=majority guarantees write acknowledgment across quorum replica nodes.

Q4: What is the MongoDB Aggregation Pipeline and how was it used in this practical?

The Aggregation Pipeline is a multi-stage framework for data processing and statistical analysis. Documents pass through sequential stages where each stage transforms the input documents. In our practical, we used $group with accumulators $sum: 1 (headcount), $avg: "$salary" (average department salary), and $sum: "$salary" (total payroll) followed by $sort: { headcount: -1 }.

Q5: What is the difference between SQL (Relational) and NoSQL (Document-based)?

SQL databases (MySQL, PostgreSQL) store structured records in tabular rows and columns with strict relational constraints and ACID transactions across tables. NoSQL Document databases (MongoDB) store self-contained, polymorphic JSON-like BSON documents. They support horizontal scaling (sharding), dynamic nested objects, arrays, and high write throughput without rigid migrations.

Q6: What are Mongoose Schema Validation and Virtuals?

Schema Validation verifies that documents conform to predefined rules (e.g., required, min, max, enum, or custom regex) before persisting to the database. Virtuals are computed document attributes that can be read or set, but are not stored directly in MongoDB (e.g., a formattedSalary virtual computing ₹${this.salary.toLocaleString()}).

Q7: How does Mongoose prevent Injection Attacks and enforce security?

Unlike raw SQL where query concatenation causes SQL Injection, Mongoose schema casting automatically sanitizes query arguments against schema types. If an attacker attempts to pass a MongoDB operator object like { "$gt": "" } to a string field, Mongoose type casting rejects or stringifies it, preventing NoSQL injection.

Q8: What are MongoDB Indexes and why are they critical in production?

Without indexes, MongoDB must perform a collection scan (inspecting every single document in the collection) to satisfy a query. An index creates a dedicated B-tree data structure that stores the values of specific fields in sorted order, reducing query lookup complexity from O(N) to O(log N). In this practical, empId and email are indexed with unique constraints.
