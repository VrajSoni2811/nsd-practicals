    Practical 06: Student RESTful API & Postman Testing

    Comprehensive guide on REST architectural constraints, HTTP status codes, idempotency, and automated test scripting with Postman.

    REST Constraints

    • Statelessness: Each request must contain all necessary context.
    • Resource Identification: Clean URI paths using nouns (/api/students).
    • Standard Verbs: GET, POST, PUT, PATCH, DELETE.
    • Self-Descriptive Messages: Clear HTTP Status Codes & MIME types.

    Postman Automated Assertions

    Postman scripts run in a sandboxed JavaScript runtime after each HTTP response is received. We test status codes, payload schemas, and response latency: 

    pm.test("Status code is 200 OK", function () {
    pm.response.to.have.status(200);
});
pm.test("Data is an array", function () {
    pm.expect(pm.response.json().data).to.be.an('array');
});
