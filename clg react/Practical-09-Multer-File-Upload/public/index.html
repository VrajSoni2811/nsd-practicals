Practical 09: Viva Voce & Architecture Questions

Comprehensive questions on Multer, MIME types, Multipart/form-data, and Storage Strategies.

Q1: What is Multer and why is standard Express body-parser insufficient for file uploads?

Multer is a Node.js middleware for handling multipart/form-data, which is the primary encoding format used for uploading files via HTML forms. Standard Express parsers (express.json() and express.urlencoded()) only parse string and JSON bodies; they cannot parse binary streams or reconstruct fragmented file chunks transmitted across multiple boundaries.

Q2: What is the difference between Multer's `diskStorage` and `memoryStorage`?

- diskStorage: Writes incoming files directly to the server's filesystem disk. It is ideal for persistent storage, large files (PDFs, videos, high-res images), and prevents server RAM exhaustion.
- memoryStorage: Buffers the incoming file in RAM as a Node.js Buffer object. It is best suited for transient files that will be immediately piped to cloud buckets (like AWS S3 or Cloudinary) or processed with in-memory image transformers (e.g., Sharp).

Q3: Why should file metadata be stored in MongoDB while files are kept on disk or cloud storage?

MongoDB documents have a strict 16MB document size limit (BSON specification) and storing raw binary blobs inside database documents degrades cache performance and inflates backups. The industry best practice is to save the physical binary payload on disk or object storage (AWS S3) and record lightweight, indexable metadata (file path, original name, MIME type, size, upload date) in MongoDB for rapid searching and querying.

Q4: How does Multer handle File Size Limits and File Type Filtering?

Multer accepts a limits option (e.g. fileSize: 5 * 1024 * 1024 for 5MB). When exceeded, Multer terminates the stream and throws a MulterError: LIMIT_FILE_SIZE. File filtering is implemented via the fileFilter(req, file, cb) hook, which inspects file.mimetype or extension and invokes cb(null, true) to accept or cb(new Error(...), false) to reject.

Q5: Why is unique filename generation critical when saving to disk?

If two users upload different files with the same name (e.g. resume.pdf), saving them with original names causes silent file overwrites and potential data leaks. Generating unique filenames using timestamps and cryptographic random strings (e.g. Date.now() + '-' + crypto.randomBytes(6).toString('hex') + ext) ensures zero collisions.

Q6: What is `multipart/form-data` encoding?

multipart/form-data divides the HTTP request body into multiple distinct parts, each separated by a unique delimiter boundary string. Each part contains its own headers (such as Content-Disposition: form-data; name="file"; filename="abc.jpg" and Content-Type: image/jpeg) followed by the binary or text payload, allowing text fields and binary files to be sent together in a single request.

Q7: How does `res.download()` work in Express?

res.download(filePath, originalFilename) transfers the file located at filePath as an attachment. It automatically sets the HTTP header Content-Disposition: attachment; filename="originalFilename", which prompts the user’s web browser to open the "Save File" dialog instead of attempting to display the raw content.

Q8: What security considerations must be addressed when building a file upload module?

1. Preventing Executable Execution: Disallow extensions like .exe, .sh, .php, .js, and store uploads outside public web root.
2. DoS Mitigation: Enforce strict file size limits.
3. Path Traversal Prevention: Sanitize file names to strip characters like ../.
4. Magic Byte Verification: Verify file headers rather than trusting the user-submitted file extension alone.
